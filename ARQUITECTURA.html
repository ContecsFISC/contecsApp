Capas de la arquitectura

Vista general

Tres capas, un solo origen

Todo se sirve desde el mismo servidor: Nginx entrega el sitio estático y hace de puerta única hacia la API; la API en Express resuelve la lógica y habla con PostgreSQL. El navegador nunca toca la base directamente.

Capa 1 · Cliente

Frontend estático

HTML + JavaScript modular servido por Nginx. Sin framework pesado: cada página carga solo su módulo. La sesión viaja en cookie; el JS nunca la ve.

Capa 2 · Servidor

API — Node.js + Express

Servicio contecs.service (systemd) escuchando en loopback. Autentica con el SSO institucional de la UTP + sesión JWT propia, autoriza por rol y resuelve cada operación en transacciones.

Capa 3 · Datos

PostgreSQL 16

Base contecs, rol de aplicación contecs_app sin superusuario. Claves foráneas reales, restricciones UNIQUE y bloqueos por fila que hacen imposible el doble escaneo. Respaldos diarios a las 3 AM.

Ciclo de una petición

Del navegador a la base, con controles en cada salto

Ninguna petición llega a la base sin pasar por Nginx (TLS + límites) y por la capa de autorización de Express. Las escrituras sensibles corren dentro de transacciones con bloqueo de fila.

1
CLIENTE
Navegador
La página llama a /api/… con la cookie de sesión que manda el navegador solo.
2
BORDE
Nginx
TLS, cabeceras de seguridad, CSP y límites de tasa. Puerta única; el backend no se expone.
3
AUTZ
Express + auth
Verifica la sesión, relee el rol de la base y aplica el permiso de la ruta.
4
DATOS
PostgreSQL
Transacción con FOR UPDATE; las restricciones UNIQUE son la red final.

Modelo de seguridad

Público y administración: dos mundos separados

La gente sin sesión solo puede hacer lo suyo. Entrar a administrar exige cuenta institucional de la UTP y un rol otorgado por un responsable.

Sin iniciar sesión

Participantes y público

  • Inscribirse al congreso
  • Ver su propia credencial con QR
  • Ver la información de su gira
Con cuenta UTP

Personal del congreso

  • Login con el SSO institucional
  • Primer ingreso = sin permisos
  • Un admin le asigna el rol
Credenciales con token de 192 bits

El QR lleva código + clave aleatoria imposible de adivinar; alterar el enlace no da acceso a nada ajeno ni al panel.

Sesión en cookie HttpOnly, firmada, solo HTTPS

Un XSS no puede robarla; el rol se relee en cada acción, así una revocación es inmediata.

Nadie se auto-aprueba un pago ni se da un rol

El registro público crea una inscripción pendiente; estados y roles los fija el servidor.

Defensa en profundidad

CSP script-src 'self', límites de tasa por IP, HSTS, archivos subidos aislados y servidos solo como descarga.

De Firebase a la VM

Migración sin romper credenciales

El sistema original vive en Firebase (proyecto contecs-fa6e6). Se exporta a JSON y se importa a PostgreSQL preservando cada id, código y token: los QR ya emitidos siguen funcionando.

Dónde vive cada cosa

Mapa del repositorio

Referencia rápida de la estructura, para ubicarse sin rebuscar. El repo se despliega a /opt/contecs en la VM.

# repo: ~/contecs-deploy   →   despliegue: /opt/contecs
app/
├─ server/            # API Express (systemd: contecs.service, :3000)
│  ├─ index.js         # monta rutas, rate-limits, arranque
│  ├─ routes/          # 27 endpoints /api/* (participantes, giras, ventas…)
│  ├─ lib/             # correo(Brevo), plantillas, participantes, giras, sesión
│  ├─ middleware/      # auth.js (sesión + permisos)
│  ├─ permisos.js      # tabla rol → permiso (autoridad real)
│  └─ templates/       # correos HTML (pago aprobado, notificación gira)
├─ postgres/
│  ├─ schema.sql       # 30 tablas
│  ├─ import.js        # Firestore JSON → Postgres (preserva QR/token)
│  ├─ exportdb.html    # exporta Firestore → JSON (correr en el navegador)
│  └─ migracion-giras-*.sql # migraciones incrementales
└─ uploads/          # comprobantes de pago
sitio/               # frontend estático (Nginx)
├─ index.html · registro.html
├─ public/          # perfil.html, gira.html (sin login)
├─ panel/           # dashboard + modulos/{admin,congreso,finanzas,logistica,voluntariado}
└─ js/              # core/ (api-client, auth, permisos, guard) · modulos/ · paginas/
# infra en la VM (fuera del repo):
#   /etc/contecs/contecs.env        secretos (BREVO_API_KEY, SESSION_SECRET, PG…)
#   /etc/nginx/sites-*/contecs      TLS, CSP, rate-limits, proxy
#   /var/backups/contecs/           respaldos diarios (3 AM) + pre-corte
